01 — Getting Started

What is Network Monitor?

Network Monitor is an all-in-one Windows desktop application for real-time network analysis, built around a dark futuristic interface with live gauges, packet capture, topology mapping, and AI-assisted investigation.

⚡ Speed Test Dashboard

Live animated gauges showing download, upload, and ping with 5-minute automatic testing and historical charts.

🦈 Wireshark Monitor

Full packet capture frontend with display filters, hex dump, stream following, statistics, and AI query.

◉ EtherApe Topology

Real-time network topology visualiser showing hosts and flows with live traffic animation.

⊙ DNS Monitoring

Continuous DNS resolution timing across 6 major hosts with history chart and jitter tracking.

✦ AI Analysis

Ask Claude to explain captures in plain English. Generate professional HTML reports with multiple queries.

⬇ Data Export

Export speed test history as CSV or JSON with flexible date range selection and folder picker.

01 — Getting Started

Installation

The installer handles all dependencies automatically. An internet connection is required during installation to download Wireshark and Nmap.

1
Run NetworkMonitorSetup.exe as Administrator

Right-click the installer and choose "Run as administrator". This is required to install Wireshark's Npcap driver.

2
Choose components

All components are selected by default. Wireshark + Npcap is required for packet capture. Nmap enables network scanning features.

3
Wait for downloads

Wireshark (~80 MB) and Nmap (~30 MB) will be downloaded and installed silently. This takes 2–5 minutes depending on connection speed.

4
Launch from Desktop or Start Menu

A shortcut is created on your Desktop and in Start Menu → Network Monitor.

⚠

Administrator rights required for capture. Packet capture (Wireshark Monitor and EtherApe) requires the application to be run as Administrator. Right-click the shortcut → Run as administrator.

System Requirements

OSWindows 10 64-bit or later
RAM4 GB (8 GB recommended for heavy captures)
Disk500 MB free (plus ~200 MB for Wireshark)
NetworkAny wired or wireless adapter supported by Npcap

01 — Getting Started

First Run

On first launch the application runs an initial speed test automatically. The main window displays five animated gauges across the top and six charts below.

ℹ

Speed test data is saved to a JSON file in your system temp folder and persists between sessions. You will see historical charts fill in over time as more tests run.

The app auto-runs a speed test every 5 minutes in a background thread. You can trigger one manually at any time with the ▶ RUN SPEED TEST NOW button.

02 — Main Dashboard

Speed Gauges

The five dials at the top of the window provide an at-a-glance view of your current network performance. Each is a 270° neon sweep gauge with animated needles.

GaugeUnitWhat it shows
Download ↓ Mbps Last measured download bandwidth. Scale auto-adjusts to 130% of your historical maximum.

Needle Easing

Gauges update every second with a 20% easing factor — the needle moves 20% of the remaining distance each tick, giving a smooth analog feel. On a manual "Run Speed Test", the needle snaps immediately to the new value.

02 — Main Dashboard

Running Speed Tests

Speed tests run automatically every 5 minutes. To run one immediately, click ▶ RUN SPEED TEST NOW in the button bar.

The button label changes to ◌ RUNNING… during the test. Results appear in the gauges and charts as soon as the test completes (typically 20–60 seconds).

How Speed Tests Work

The app uses the Ookla Speedtest CLI (speedtest.exe) with three fallback attempts:

1
JSON mode

Fastest and most accurate. Returns structured data directly.

2
Plain text mode

Falls back to parsing human-readable output if JSON fails.

3
Bare run

Last resort — runs speedtest.exe with no flags and parses any output found.

⚠

Speed test results require an active internet connection. If all three attempts fail, check that speedtest.exe is present in the install folder and that your firewall is not blocking it.

02 — Main Dashboard

DNS Monitoring

Click ⊙ MONITOR DNS to run a DNS resolution check. The app resolves these six hosts and measures the wall-clock time for each:

  • google.com
  • cloudflare.com
  • microsoft.com
  • amazon.com
  • bbc.co.uk
  • github.com

The average of all successful resolutions is recorded and displayed on the DNS dial and in the DNS History chart. Up to 500 readings are retained.

Interpreting DNS Times

RangeAssessment
< 20 msExcellent — fast local or ISP DNS
20–50 msGood — normal for most connections
50–100 msModerate — consider using 8.8.8.8 or 1.1.1.1
> 100 msSlow — DNS may be causing browsing delays
💡

High DNS times can make websites feel slow even when your broadband speed is fine. Try setting your DNS server to 1.1.1.1 (Cloudflare) or 8.8.8.8 (Google) in your network adapter settings.

03 — Wireshark Monitor

Wireshark Monitor

A full-featured dark-themed packet capture and inspection tool built on top of tshark (Wireshark's command-line engine). Accessed via the 🦈 WIRESHARK button on the main dashboard.

📡 Live Capture

Select any network interface and start capturing packets in real time with colour-coded protocol rows.

🔍 Display Filters

Filter the visible packet list using Wireshark filter syntax without stopping the capture.

📋 Packet Detail

Click any packet to see the full decoded protocol tree and hex dump side by side.

📊 Statistics

Protocol hierarchy, conversations, endpoints, I/O graph, DNS stats, HTTP stats, and more.

💾 PCAP Files

Open existing PCAP/PCAPNG files or save the current capture for later analysis.

✦ AI Query

Ask Claude to explain what happened in the capture in plain English and export a PDF report.

03 — Wireshark Monitor

Starting a Capture

1
Select an interface

Choose your network adapter from the Interface dropdown. Wi-Fi and Ethernet adapters are listed with friendly names. Run as Administrator if the list is empty.

2
(Optional) Set a Capture Filter

Enter a BPF filter in the Capture Filter field before starting. Examples: port 80, host 192.168.1.1, tcp. This filters at the driver level and reduces overhead.

3
Click ▶ Start Capture

Packets appear in the list in real time, colour-coded by protocol. The packet counter updates in the toolbar.

4
Click ◼ Stop when done

The capture is saved automatically as a PCAP file. The status bar shows how many packets were recorded.

🔒

Administrator required. Packet capture will fail silently or show an "access denied" error without admin rights. Right-click the application shortcut and choose "Run as administrator".

Display Filters

Display filters narrow the visible packet list without stopping the capture or deleting data. They use standard Wireshark filter syntax.

Common Filter Examples

FilterShows

udpAll UDP packets
dnsAll DNS queries and responses
httpUnencrypted HTTP traffic
tlsEncrypted TLS/HTTPS traffic

ip.src == 10.0.0.5Traffic from a specific source IP
tcp.port == 443Traffic on port 443 (HTTPS)
icmpPing packets
frame.len > 1000Large packets only

Press Enter or click Apply to activate the filter. Click ✕ Clear to remove it and show all packets.

Right-Click Quick Filters

Right-click any packet row to access quick filter options:

  • Filter by Source IP — shows only traffic from that address
  • Filter by Destination IP — shows only traffic to that address
  • Filter by Protocol — shows only that protocol type
  • Follow TCP/UDP Stream — reconstructs the full conversation
  • Copy Source IP / Dest IP / Info — copies to clipboard

03 — Wireshark Monitor

PCAP Files

Opening a PCAP

Click 📂 Open PCAP and select any .pcap, .pcapng, or .cap file. The file is loaded and all packets are displayed. You can then apply display filters and run statistics on the file.

Saving a Capture

Click 💾 Save PCAP to save the current capture to a chosen location. The file is always saved in PCAP format and can be opened in Wireshark, tcpdump, or any other compatible tool.

ℹ

During a live capture, tshark automatically writes packets to a temporary PCAP file in your system temp folder. This is what gets loaded when you click Save PCAP.

03 — Wireshark Monitor

AI Query

Click ✦ AI Query to open the AI analysis window. This sends a summary of your capture to Claude and lets you ask questions in plain English.

1
Enter your API key

Paste your Anthropic API key in the key field. Get one free at console.anthropic.com. Click Save Key to remember it for future sessions.

2
Click a quick prompt or type your own

Six quick prompts are provided: Summarise, Suspicious patterns, Top hosts, DNS lookups, Network errors, Connections established.

3
Click Ask AI or press Enter

The capture summary (protocol breakdown, top IPs, sample packets, tshark stats) is sent to Claude. The response appears in the text area below.

What Context Is Sent

  • Total packet count and capture duration
  • Full protocol breakdown with counts
  • Top 10 source and destination IPs by packet count
  • Average packet rate
  • First 40 and last 20 packets (full detail)
  • tshark protocol hierarchy, IPv4 conversations, DNS tree
💡

You do not need to stop the capture before using AI Query. The context is built from the packets currently visible in the list (including any active display filter).

03 — Wireshark Monitor

Generating Reports

Build a multi-section HTML report from multiple AI queries:

1
Ask a question and get an AI response

Any question — summarise, security analysis, specific host investigation, etc.

2
Click ＋ Add to Report

The question and answer are saved to the report queue. The counter updates: "Report: 2 entries".

3
Ask more questions and add them

Each query becomes its own section. Use the queue panel at the bottom to reorder (▲ ▼) or remove (✕) entries.

4
Click 📄 Generate Report

Choose a save location. An HTML file is created and opened in your browser automatically.

5
Print to PDF from your browser

In Chrome or Edge: File → Print → Destination: "Save as PDF". The report is print-optimised.

ℹ

Reports are self-contained HTML files — no internet connection needed to open them. They include the capture stats table, timestamps for each query, and all AI responses with markdown formatting rendered correctly.

04 — EtherApe Monitor

EtherApe Monitor

A real-time network topology visualiser that shows hosts as nodes and network flows as animated lines. Accessed via the ◉ ETHERAPE button on the main dashboard.

🌐 Live Topology

Hosts appear as nodes sized by traffic volume. Flows are animated with pulse dots showing data direction.

🔬 Flow Inspection

Click any flow line on the canvas or in the table to see full IPs, protocol, packet count, data transferred, and average packet size.

📁 PCAP Replay

Load a PCAP file and replay it at 0.1× to 16× speed (or unlimited) to visualise historical captures.

🔤 Font Control

Adjust font size (6–24) and family for all labels from toolbar 2. Changes apply to the whole window.

04 — EtherApe Monitor

PCAP Replay

Replay a previously captured PCAP file through the topology visualiser to investigate historical traffic.

1
Click 📂 Open PCAP

Browse for a .pcap, .pcapng, or .cap file. The filename appears in amber text in the toolbar once loaded.

2
Set replay speed

Use the Speed spinner: 0.1×, 0.25×, 0.5×, 1× (real-time), 2×, 4×, 8×, 16×, or 0 (unlimited speed — no timing delays).

3
Click ⏵ Replay

The canvas clears and traffic replays. Progress shows in the status bar as "packet N / total (%)". The topology builds as packets are processed.

4
Click ⏹ Stop Replay to halt

The topology freezes at the point where replay was stopped. You can then inspect flows and run AI queries against the replayed data.

ℹ

Live capture and PCAP replay are mutually exclusive — you cannot run both at the same time. Starting a replay with a live capture active will do nothing.

05 — Reference

Troubleshooting

Packet Capture Fails Immediately

🔒

Most common cause: not running as Administrator. Right-click the app shortcut → Run as administrator. Npcap requires elevated privileges to capture packets.

If you are running as admin and capture still fails, check:

  • Npcap is installed — check Add/Remove Programs
  • Try a different interface from the dropdown
  • The error dialog will show the exact tshark error message

Speed Test Shows "All Attempts Failed"

  • Check that speedtest.exe is in the application install folder
  • Ensure your firewall / antivirus is not blocking speedtest.exe
  • Check your internet connection
  • The console output (if running with console=True) will show detailed error messages

EtherApe Shows "No Traffic"

  • Make sure you clicked ▶ Start (not just opened the window)
  • Check the selected interface has active traffic — try your Wi-Fi or Ethernet adapter
  • Loopback interface only shows local traffic between processes on the same machine
  • If using a BPF filter, verify the filter syntax is correct

AI Query Returns "401 Unauthorized"

  • Your API key is missing or incorrect — re-enter it in the API key field
  • Get a key at console.anthropic.com → API Keys → Create Key
  • Check that you clicked Save Key after entering it

Report Generation Fails

  • The report requires at least one entry — click ＋ Add to Report after getting an AI response
  • Check you have write permission to the chosen save location
  • Try saving to the Desktop if the chosen folder fails

DNS Gauge Shows 0

The DNS gauge only updates when you click ⊙ MONITOR DNS. It does not update automatically — click it whenever you want a fresh reading.

Application Freezes During Heavy Capture

The Wireshark Monitor uses a batched update system that inserts packets in groups of 150 every 100ms. If the UI feels sluggish with very high traffic, try applying a display or capture filter to reduce the packet rate.
