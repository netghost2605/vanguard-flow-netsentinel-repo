01 — Getting Started

What is Vanguard Flow NetSentinel?

It started as a speed-test monitor and grew into a full local network-operations console — measuring your connection, capturing and visualizing your traffic, watching for scanners and intrusions, and explaining what it sees in plain language via a locally-running AI. Everything runs from one Python process; you can drive it from the desktop windows or from any browser on your network.

This manual documents the app's current sidebar + card interface (window title Vanguard Flow NetSentinel). If you've used an older build with big dial-style speed gauges, that "Classic" dashboard has been replaced — this manual only covers the interface the app actually launches today.

What's in the box

📶Speed & Quality

Multi-engine speed tests, bufferbloat grading, DNS timing, outage detection, VDI health, an ISP evidence-pack PDF.

🦈Wireshark Monitor

A full tshark-backed capture window with filters, Statistics/Analyse menus, and PCAP open/save.

🌐Topology & 3D

An EtherApe-style live graph, a WebGL 3D scene with a rotating globe, sonar & threat radar, and a flow-map view.

🍯Honeypot & Firewall

29 decoy ports with a tarpit, cross-platform firewall blocking, a one-click kill switch, and country blocking.

✦Local AI

Runs on Ollama by default — no API key, no cloud account. Anthropic is available as an optional alternate provider.

⊞Remote & Web

Poll headless agents on other machines, connect a standalone client, or just open the built-in web dashboard.

ℹ

No keyboard shortcuts. The current interface is entirely mouse-driven — there are no accelerator= hotkeys bound anywhere in the main dashboard, Wireshark Monitor, or Topology window. Where this manual gives a "quick reference," it's a table of buttons, not keys.

01 — Getting Started

Installation

The same source file builds for both Windows and Linux.

Windows

1
Run NetworkMonitorSetup.exe

Built from installer.nsi via build_installer.bat. No third-party NSIS plugin is required.

2
Choose a preset

Full installs the monitor app plus capture/AI components; Client only installs just nm_client.py for a second machine that only needs to view the dashboard.

3
Let it fetch dependencies

The installer downloads Npcap, Wireshark, Ollama, and the librespeed-cli speed-test CLI directly from each project's own site during setup — nothing third-party is bundled or redistributed. Any step that fails to download shows a message box telling you exactly what to install manually and from where.

4
Run as Administrator

Needed for packet capture, the firewall/kill switch, and the honeypot's low-numbered decoy ports.

Linux

1
Build a package

./build-linux.sh deb produces a .deb; ./build-linux.sh appimage produces a portable AppImage.

2
Install with apt, not dpkg

sudo apt install ./netsentinel_1.0.0_all.deb — using apt instead of raw dpkg -i lets dependencies resolve automatically.

3
Join the wireshark group

Needed for packet capture without running the whole app as root. Firewall/kill-switch features still need sudo/root.

System Requirements

PlatformRequirement
WindowsWindows 10 or later, 64-bit. Administrator for capture, firewall, kill switch, and low-numbered honeypot ports.
LinuxAny recent distro. wireshark group for capture; root/sudo for firewall and kill-switch features.
BothOutbound internet access is used for: geolocation (ip-api.com), threat-intel feed downloads, and Ollama's first-run model pull (~2GB). The app still works offline — those features just degrade gracefully.
01 — Getting Started

First Run

1
Launch the app

Desktop/Start Menu shortcut, or run speedtest_monitor.py directly with Python. The main window opens titled Vanguard Flow NetSentinel, sized 1400×820.

2
Ollama starts itself, quietly

Before the window even appears, a background thread tries to launch ollama serve if Ollama is installed, and pulls the default model (llama3.2, ~2GB) the very first time. There's no splash screen for this — if it fails, AI features just show a plain-English error later; everything else keeps working.

3
The embedded web server comes up on port 8765

Open http://localhost:8765 in a browser at any time to reach the same dashboard from your phone or another machine on the network.

4
Point Settings at your tools

Click ⚙ PREFS in the sidebar and check the Speedtest CLI and Wireshark / tshark path fields — the app auto-detects both where possible, but use Test to confirm.

5
Run your first test

Click ▶ RUN in the left sidebar. A test also runs automatically every 5 minutes by default.

✓

The status bar along the bottom of the main window shows live green/red dots for speedtest.exe and tshark availability, the web server's port, and whether SQLite or the legacy JSON store is active — a quick way to confirm everything found what it needs.

02 — Main Dashboard

Speed Tests & Bufferbloat

Running a Test

Click ▶ RUN in the sidebar for a manual test, or let the schedule handle it — ⚙ PREFS → Speed Test Schedule → "Run every ___ minutes (1–1440)" with quick-pick buttons (1m 5m 10m 15m 30m 1h 2h). Default is every 5 minutes, and a change takes effect once the current interval finishes.

Which Engine It Uses

There's no engine picker in the UI. The app auto-detects whichever speed-test CLI is pointed to by ⚙ PREFS → Speedtest CLI → the speedtest.exe path field, and normalizes its output regardless of which of the three it is:

  • librespeed-cli (LGPL) — what the Windows installer fetches automatically.
  • speedtest-cli / "sivel" (Apache) — also auto-detected if present.
  • Ookla's own CLI — used if you already have it installed, but never bundled or auto-downloaded (its license forbids redistribution).

Bufferbloat Grade (A+ to F)

Shown in ◈ QUALITY → the Quality tab, as a large letter grade with the added-latency-under-load figure beneath it:

GradeAdded latency
A+under 5 ms
Aunder 30 ms
Bunder 60 ms
Cunder 200 ms
Dunder 400 ms
F400 ms or more

Measured by pinging continuously while a speed test saturates the link, so it shows whether the connection falls apart under load — not just how fast it is sitting idle.

02 — Main Dashboard

DNS Monitoring

Click ⊙ DNS to run a check on demand, or watch the DNS gauge card and the "DNS history" chart update automatically alongside every speed test. There's no separate DNS window on the desktop — the per-host breakdown only shows up in a generated report.

Six hosts are resolved and timed by default:

google.com  ·  cloudflare.com  ·  microsoft.com  ·  amazon.com  ·  bbc.co.uk  ·  github.com

Change the list at ⚙ PREFS → DNS Check Hosts (comma-separated), with a Reset to defaults button. A host that fails to resolve counts as a failure; the DNS reading is the average of whichever hosts succeeded.

02 — Main Dashboard

Heatmap & Outages

Time-of-Day Heatmap

Sidebar ▦ HEATMAP opens a 7×24 grid — weekday down the side, hour across the top — coloring every cell by the median of download, upload, or ping (pick with the Metric dropdown) over a rolling window of 7 / 30 / 90 / 365 days (Window dropdown, default 90). A white-outlined box marks the current weekday/hour; hover any cell for its sample count and last reading.

ℹ

Each cell aggregates every occurrence of that weekday+hour in the window — e.g. every Sunday at 1pm — not just today, so patterns like "evenings are always slow" become visible after a week or two of data.

Outage Log

Sidebar ⚠ OUTAGES opens a table of every gap in successful tests over the last 90 days — columns Went down, Came back, Duration, most recent first — with a header summary like "3 outages · 2.1 hrs total downtime · uptime 99.87%".

02 — Main Dashboard

VDI Session Health

Diagnoses "my remote desktop feels laggy" in real time by watching active VDI sessions on the machine.

Lives in the ◱ MONITOR window, under the VDI tab. It watches for active sessions on these ports and labels the protocol accordingly:

PortProtocol
3389RDP
4172PCoIP
22443Blast Extreme
8443Blast (UAG)

A background worker pings the session's remote host every 15 seconds and grades it: good, fair (loss ≥1% or RTT ≥80ms), poor (loss ≥5% or RTT ≥150ms), or unknown. A transition into "poor" raises an alert (deduped for 10 minutes). The table shows Health, Protocol, Client, Host, RTT, Loss, and Bandwidth per session.

02 — Main Dashboard

Export & Reports

Three distinct ways to get data out — pick based on what you need.

Export Speed Data (CSV)

Sidebar ⬇ EXPORT — pick a Period (Today, Last 7 days, Last 30 days, All; "Today" means since local midnight) and click Export CSV. Suggested filename: speedtest_YYYYMMDD_HHMM.csv, columns Timestamp, Download (Mbps), Upload (Mbps), Ping (ms). CSV only — no JSON option in this particular dialog.

Generate Network Report

Sidebar ⎙ REPORT opens a much richer dialog that builds an interactive HTML report:

  • Time period: Last 1 hour / 6 hours / 24 hours / 7 days / 30 days / All Time
  • Contents: checkboxes for Speed History, DNS Performance, Remote Agents, Topology & Traffic, Firewall Logs, Honeypot Activity (or just "Full Summary")
  • Storage: defaults to ~/Documents/NetworkMonitor, filenamed nm_report_YYYYMMDD_HHMMSS.html, with a 📂 View Previous Reports browser
  • Schedule: optional Hourly/Daily/Weekly auto-generation at a chosen time of day

The generated report has its own embedded AI panel (✦ Analyse Report) that calls back to the desktop app's local web server — so that button only works while the app is running.

✓

This report also embeds Chart.js inline (cached to ~/.nm_chartjs.js after the first fetch), so its charts still render if you reopen it offline later — only the AI button needs the app running.

03 — Wireshark Monitor

Filters

Display Filter

The Display Filter: box takes normal Wireshark syntax (e.g. ip.addr == 192.168.1.1 && tcp) — type and press Return, or click Apply. ✕ Clear resets it. It's a plain text entry with no autocomplete or filter history.

Capture Filter (BPF)

A separate combobox, applied only when a capture starts, pre-loaded with common presets: tcp, udp, icmp, arp, per-port presets (port 80, port 443, port 53, port 22, port 3389...), DHCP/NTP/mDNS/SSDP ports, host/net matches, SYN-only and setup/teardown TCP-flag filters, and packet-size filters. You can also type your own.

Right-Click Quick Filters

Right-click any packet row for: Follow TCP Stream, Follow UDP Stream, Copy Source IP, Copy Dest IP, Copy Info, Filter by Source, Filter by Dest, Filter by Protocol.

03 — Wireshark Monitor

PCAP Files

📂 Open PCAP accepts .pcap, .pcapng, or .cap. 💾 Save PCAP writes .pcap or .pcapng — both operate on the same raw scratch file tshark wrote (nm_wireshark.pcap in the OS temp folder), so it's a straight copy with no format conversion.

03 — Wireshark Monitor

AI Query

✓

Runs on Ollama by default — no API key needed. Anthropic is available as an optional alternate provider if you switch to it and supply your own key.

Click ❆ AI Query to open AI Capture Analysis. The AI: dropdown offers Ollama (local) or Anthropic; picking Ollama hides the key field entirely (status reads "Provider: Ollama (local, no key)"). Picking Anthropic reveals a masked key entry, Show/Hide, and Save Key.

Quick Prompts

  • Summarise what happened in this capture
  • Are there any suspicious or unusual patterns?
  • Which hosts are generating the most traffic?
  • What DNS lookups were made?
  • Are there any signs of network errors or retransmissions?
  • What connections were established and to where?

Or type your own question and click Ask AI (or press Return).

What Context Is Sent

Protocol/host counts, top 10 sources and destinations, capture duration, packet rate, the first 20 and last 10 packets, and (if a capture file exists) tshark's own protocol-hierarchy, IPv4-conversation, and DNS-query stats — capped at 6,000 characters.

⚠

If Ollama isn't installed, the app tells you exactly how to get it (a platform-specific one-liner) rather than failing silently — everything else in the app keeps working while AI is unavailable.

03 — Wireshark Monitor

Generating Reports

Inside the AI Query window: ask a question, then click + Add to Report to queue that Q&A. Reorder with ▲ Move Up / ▼ Move Down, drop one with ✕ Remove, then click 📄 Generate Report.

The output is a single self-contained HTML file (capture_analysis_YYYYMMDD_HHMMSS.html) with a summary table and one card per queued question/answer — no external assets, so it opens correctly offline forever. A footer note explains how to print it to PDF from your browser.

ℹ

The report's subtitle line is hardcoded to read "Powered by Claude (Anthropic)" even when Ollama actually answered the questions — a cosmetic leftover, not a sign your API key is being used.

04 — Topology & Visualization

Topology Canvas

Reading the Display

Left-click a node to pin/drag it and see its detail; left-click a flow line (or its curve, in Sankey layout mode) to open Flow Detail. Double-click a node for its geo/firewall popup. Toggle between straight-line and curved-Sankey layouts with ⇉ SANKEY / ◎ RADIAL.

Traffic Decay

Unless Hold is checked, every node and flow fades continuously — thickness shrinks by a factor of 0.9985 on every ~50ms render tick — and is removed once it's been idle roughly 5 minutes (nodes) or 2 minutes (flows). It's a smooth fade, not a hard cutoff.

Limits

The canvas shows at most 500 nodes and 2,000 flows at once (the same caps apply to the 3D view).

World View

Wraps every host onto a rotating globe at its real latitude/longitude (hosts sharing a location fan into a ring), flows follow great-circle arcs, and a real day/night terminator is computed from the current UTC time and day of year — genuinely tracking where it's actually daytime on Earth right now. The globe auto-rotates roughly once per minute; click to pause it, press the button again to exit.

04 — Topology & Visualization

Sonar & Threat Radar

Sonar Radar

A mode inside the Top Flow Talkers overlay (toggle ↙ INCOMING). Every host plots as a blip at its real location — outgoing traffic cyan, incoming green, blip size by volume, blocked hosts red with a cross. An audible ping fires only for genuinely new connections (the existing list is seeded silently on open, so it doesn't burst-ping everything at once).

Threat Radar

A dedicated page at http://localhost:8765/threats, or the topology toolbar's ⚠ THREATS button. Same sweep/projection as the sonar scope, but scoped to hostile hosts only — honeypot sources, blocked hosts, attack traffic, and flagged-but-not-yet-blocked hosts, each carrying a country flag, with critical threats pulsing an expanding ring.

A third, narrower instance of this same radar is embedded directly in the Honeypot window, scoped just to honeypot hit geography.

04 — Topology & Visualization

Flow Map (Sankey)

Browse to http://localhost:8765/sankey ("Top Flow Talkers"). Internal hosts form a left-hand column, external hosts a right-hand column, and each flow between them is a gradient-filled ribbon whose width scales with byte volume — fully opaque at both ends, translucent in the middle, with a soft glow and small particles animating along its length to show direction. Side panels list Active Hosts, Active Flows, and Flow Detail, with the same ⚠ BEHAV / ◉ TRAFFIC / ⚠ IDS analysis buttons as elsewhere.

Top Talkers

Browse to http://localhost:8765/talkers. A live-ranked table, columns #, Host, Org/Country, Proto, Traffic, Packets, Share, refreshing every 2 seconds (capped at the top 100 hosts by bytes) with a ⏸⏸ PAUSE toggle to freeze it for reading. Org/country come from a background geo-IP lookup, so they fill in progressively rather than appearing instantly.

Devices & Vendors

Device identification isn't one single screen — it's the same MAC-vendor lookup surfacing in two places:

  • Desktop: ◈ QUALITY → the Devices tab — a table of IP / MAC / Name / Last seen, with ⟳ Scan network (ARP scan) and ✎ Rename selected buttons.
  • Web: /monitor → the Devices tab — a card per device with an online/offline dot, vendor-derived name, IP+MAC, and last-seen time; tap a card to rename it.

05 — Security & Threats

Honeypot

Binds 19 TCP and 10 UDP decoy ports mimicking real services, fingerprints who connects, and can stall them for up to 10 minutes without wasting real bandwidth.

Open it from the topology toolbar's 🍯 HONEYPOT button (tries the web console at /honeypot first, falls back to a desktop window) or browse directly to http://localhost:8765/honeypot.

Connections are fingerprinted against roughly 30 known scanner/tool signatures (libssh, paramiko, SMB probes, admin-panel scans, CGI exploits, VNC handshakes, and more) and fake service banners are sent for realism.

Tarpit

TCP connections can be held open up to 10 minutes, drip-fed one byte every 2–6 seconds, capped at 400 concurrent held sockets. UDP decoys are never tarpitted and never reply, so the honeypot can't be abused as a reflection amplifier. Hits are logged and alerted before tarpitting starts, so the hold never delays detection.

05 — Security & Threats

Firewall Management

Open via the topology toolbar's ⛔ FIREWALL button, or by clicking the "N blocked" pill visible in several other windows. The window itself only lists and unblocks — blocking a host is done from wherever you spot it (honeypot's Block Selected, a topology right-click, country/range blocking, or auto-block).

A live search box filters the table by IP, device name, or rule name as you type — no Enter needed — with a "N of M shown" counter. Columns: Blocked address, Name, Rule name, State.

Backend

Windows uses netsh advfirewall rules; Linux uses its own dedicated nftables table (nm_sentinel) so your existing ruleset is never touched. Every rule this app creates is named NM_BLOCK_<ip>, so they're easy to spot if you ever inspect the firewall directly.

⚠

If the window shows "NOT RUNNING ELEVATED," new blocks will fail silently at the OS level — restart the app as Administrator (Windows) or with sudo (Linux).

05 — Security & Threats

Kill Switch

A single button — ⏻ KILL CONNECTION — in the Topology window's toolbar and on the web 3D/flow-map views (not on the main speed-test dashboard). Clicking it shows a confirmation dialog, then blocks all inbound and outbound traffic on the machine.

✓

Loopback (127.0.0.1) is never filtered by either backend, so the local dashboard stays reachable and you can turn it back off from the same button — now reading ⏻ RE-ENABLE CONNECTION — without needing another machine.

Requires Administrator/root. If left on from a previous session, the app correctly detects and reflects that state on reopening rather than losing track of it.

05 — Security & Threats

Country / Geo Blocking

In the topology toolbar: a COUNTRY box filters what's displayed (not blocking), while BLOCK CC (a 2-letter code) + ⛔ BLOCK blocks every currently-known IP from that country and enrolls it for future auto-blocking — there's no separate toggle for the two; blocking a country always does both. A BLOCK RANGE field alongside it blocks by CIDR instead. 📋 MANAGE opens a window listing every blocked country with a per-row Unblock button.

⚠

Auto-blocking newly-seen IPs from a blocked country only runs on Windows in this build. The initial "block everyone currently known" action works on both platforms; the ongoing watch for new arrivals from that country does not run on Linux.

Geolocation has no bundled database — it calls the free public ip-api.com service live and caches results, so country blocking (and the radar/talkers views) depend on outbound internet access and that service's rate limits.

05 — Security & Threats

Threat-Intel Feeds

Three feeds are pre-configured and refreshed automatically every 8 hours:

  • Emerging Threats — IP block-rule list
  • Feodo Tracker — abuse.ch's C2 IP blocklist
  • ET Compromised IPs — Emerging Threats' compromised-hosts list

Each feed is cached to disk, so a download failure falls back to the last good copy rather than leaving you unprotected. A match against any feed raises a critical alert (deduped hourly per IP). Status shows in the desktop Alerts tab and the web /monitor page as "N bad IPs · M ranges · X countries seen," with a relative "last updated" time.

ℹ

Adding a custom feed isn't exposed as a form in this build — it's read from a threat_feeds array in the JSON config file, which currently needs hand-editing rather than a Settings field.

05 — Security & Threats

ML Anomaly Detection

A local Isolation Forest model (scikit-learn) scores live flows on byte volume, packet count, average packet size, destination port, and whether the destination is public — flagging statistical outliers as "unusual traffic profile." It needs at least 8 concurrent flows to run at all.

✓

Entirely local — no cloud dependency — and it no-ops gracefully if scikit-learn/numpy aren't installed, rather than erroring.

Runs as part of the always-on flow-watch loop (see Continuous Flow-Watch) alongside rule-based checks and a beaconing detector; findings surface in the Topology window's red alert strip.

05 — Security & Threats

Attack Drill

The ☠ ATTACK SIM button — present in the Topology toolbar, the 3D view, and the Top Flow Talkers page (all wired to the same shared toggle, so starting it anywhere shows it everywhere) — simulates realistic-looking hostile traffic to demonstrate what a genuine detection and block looks like, safely.

Every simulated source comes from IP ranges reserved for documentation use — 192.0.2.0/24, 198.51.100.0/24, 203.0.113.0/24 — spread across 14 fictional cities worldwide, each tagged with a plausible attack type (SSH brute force, port scan, UDP flood, SQL injection, and more) and labelled SIM everywhere it appears.

A new hostile appears roughly once per second (up to 12 live at a time), ramps simulated traffic for 1–4 seconds, then "detonates" — a real block-event fires (the same bookkeeping real blocks use, so the UI reacts identically: a shock-ring and BLOCKED marker on the radar/globe) without ever writing an actual OS firewall rule or touching a real host. Toggle it off to clear every live hostile immediately.

06 — AI Analysis

How AI Works Here

Every AI feature in the app funnels through the same small set of shared logic — understand this once and the rest follows.

On launch, a background thread tries to start ollama serve if Ollama is installed but not already running, and pulls the default model — llama3.2 — the first time, silently (log-only, no splash dialog). If Ollama isn't installed at all, every AI feature keeps working in the sense that the rest of the app is unaffected — you just get a plain-English error explaining how to install it (a one-line command specific to your OS) when you try to use one.

Switching to Anthropic

There's no central AI settings tab — the provider dropdown lives locally in each AI-enabled window (Topology's Flow Detail panel, and the AI Capture Analysis window), and the choice is shared across all of them via files in your home directory. Pick Anthropic, paste an API key, and every AI feature in the app switches to it — including the model name, which defaults to claude-haiku-4-5-20251001.

06 — AI Analysis

Continuous Flow-Watch

Internally called "AI Watch." It has no manual toggle — the moment the Topology window opens, it starts scanning live flows every 30 seconds, and stops only when the window closes.

Each pass layers three checks: a rule-based pre-screen (known-bad ports, high-risk countries, large uploads to public IPs), the local ML anomaly detector, and a beaconing detector that flags suspiciously regular, low-variance contact intervals (possible C2). Up to 40 active flows are then sent to the AI for a confirmation pass; if the AI is unreachable, the rule-based and ML hits are used as-is rather than losing the check entirely.

Findings appear in a red AI THREAT ALERTS strip at the bottom of the Topology window (and mirrored into the Geo Map window), with matching red-ring highlights on flagged nodes.

06 — AI Analysis

Daily Briefing

A plain-language summary of the last 24 hours — download/upload/ping averages, gateway uptime %, alert counts, newly-seen devices, top local talkers, latency to key targets, and threat-feed status — generated automatically once a day (default 8am local time, checked every 10 minutes) and pushed as a notification, or generated on demand with the Generate now button in the Analytics tab of the ◱ MONITOR window, or via the web /analytics page.

ℹ

The 8am default trigger time has no Settings field yet — it's the briefing_hour config key, editable in the JSON config if you want it earlier or later.

If the AI call fails, the briefing degrades to the raw stats as plain text rather than showing nothing.

Thresholds & Alerts

Settings → Alerts → master checkbox "Notify me when the connection misbehaves", then per-metric thresholds — leave any box empty to skip that rule:

Download <  ·  Upload <  ·  Ping >  ·  Jitter >  ·  Loss >  ·  Bufferbloat >

Data & Storage

SQLite is the primary store; any existing legacy JSON data is migrated in automatically on first run and backed up alongside it. Speed-test history lives in one database file; devices, alerts, honeypot hits, and firewall events live in a deliberately separate one, so a problem in either can never corrupt the other.

Settings → Data → "Purge corrupt speed readings…" clears download/upload values that fall outside a sane range (leftover from an old units bug) — it backs up the database first, automatically, before touching anything, and only clears the affected fields, leaving timestamps/ping/jitter/loss/bufferbloat untouched.

10 — Reference

Troubleshooting

AI Query Returns an Error

AI runs locally via Ollama by default — no API key needed. Install it from ollama.com and pull a model (ollama pull llama3.2). The app tries to start Ollama automatically on launch; if that fails, run ollama serve manually and confirm the model name matches one from ollama list. Only relevant if you've switched providers: check your Anthropic API key and that the machine can reach api.anthropic.com over HTTPS.

Packet Capture Fails Immediately

Confirm tshark is installed and its path is set correctly in Settings, and that the app is running elevated (Administrator on Windows, or your user is in the wireshark group / running with sudo on Linux).

Speed Test Shows "All Attempts Failed"

Check the Speedtest CLI path in Settings and click Test. If it's blank or wrong, the installer's downloaded librespeed-cli.exe normally sits right next to the app executable — reinstalling or rerunning the installer's speed-test-CLI step will restore it.

Firewall / Kill Switch Actions Fail

Almost always a permissions issue — restart as Administrator (Windows) or with sudo (Linux). On Linux, confirm nftables is installed (sudo apt install nftables).

Country Auto-Block Isn't Catching New IPs

Expected on Linux in this build — the initial block runs cross-platform, but the ongoing watch for newly-seen IPs from a blocked country is currently Windows-only.

ISP Evidence Pack Shows 0 for Advertised Speed

There's no Settings field for this yet — add advertised_down / advertised_up (Mbps) to speedtest_config.json directly, then regenerate the pack.

DNS Gauge Shows 0

All six monitored hosts failed to resolve — check general internet/DNS connectivity, or that your monitored host list (Settings → DNS Check Hosts) hasn't been set to something unreachable.
